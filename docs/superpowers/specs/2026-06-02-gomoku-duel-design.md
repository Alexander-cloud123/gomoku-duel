## 1. 项目概述

开源浏览器五子棋游戏，支持两台电脑通过 WebRTC 点对点联机对战。房主独享 AI 智能辅助（落子推荐 + 威胁提醒 + 胜率评估），访客无辅助。

### 核心需求

| 需求 | 决策 |
|---|---|
| 联机方式 | WebRTC P2P（PeerJS 公共云信令） |
| AI 辅助程度 | 综合辅助（落子推荐 + 威胁提醒 + 胜率评估） |
| 棋力差距 | 房主远弱于访客，AI 需接近"作弊级"确保 50%+ 胜率 |
| 运行形式 | 浏览器网页 |
| 辅助权限控制 | 房间号末尾带 `*` 标识辅助权限 |
| 房间号分发 | 房主创建房间，自动生成 6 位房间号，发给访客 |
| 棋盘规格 | 15×15 标准棋盘 |
| 游戏规则 | 无禁手 |
| 悔棋/和棋 | 均支持（需对方同意） |
| 界面风格 | 现代简约风（浅色背景） |
| 技术栈 | 纯 HTML/CSS/JavaScript（无框架），PeerJS CDN 引入 |

## 3. WebRTC 联机方案

### 方案选型：PeerJS 公共云 + 6 位房间号

- 使用 PeerJS 库（CDN 引入）简化 WebRTC 信令
- 房主创建房间时，PeerJS 自动在公共云注册一个 peer ID（`gomoku-` + 6 位房间号）
- 访客输入房间号后，PeerJS 自动找到房主并建立 P2P 连接
- 游戏数据完全 P2P 传输，不经过 PeerJS 云

### 连接流程

```
房主 (玩家A)                      访客 (玩家B)
   │                                  │
   │  1. 点击"创建房间"                │
   │  → 连接 PeerJS 云                │
   │  → 生成 6 位房间号 "DRAGON"      │
   │  → 显示"等待对手加入..."          │
   │                                  │
   │  2. 把 "DRAGON" 发给 B           │
   │  （微信/QQ/口头/短信）            │
   │                                  │
   │                                  │  3. 点击"加入房间"
   │                                  │  → 输入 "DRAGON"
   │                                  │  → PeerJS 自动找到 A
   │                                  │
   │  ◄──── P2P 连接自动建立 ────►    │
   │                                  │
   │  4. 双方进入对局                  │
```

### 数据交换协议

JSON 格式消息：

| 消息类型 | 方向 | 作用 | 示例 |
|---|---|---|---|
| `MOVE` | 双方互发 | 落子通知 | `{type:"MOVE", x:7, y:7, color:"black"}` |
| `UNDO_REQUEST` | 双方 | 申请悔棋 | `{type:"UNDO_REQUEST"}` |
| `UNDO_RESPONSE` | 反向 | 同意/拒绝悔棋 | `{type:"UNDO_RESPONSE", accept:true}` |
| `DRAW_REQUEST` | 双方 | 申请和棋 | `{type:"DRAW_REQUEST"}` |
| `DRAW_RESPONSE` | 反向 | 同意/拒绝和棋 | `{type:"DRAW_RESPONSE", accept:false}` |
| `RESTART` | 双方 | 再来一局 | `{type:"RESTART"}` |
| `PING/PONG` | 双向 | 心跳检测（5秒间隔） | `{type:"PING"}` |

### NAT 穿透

使用 Google 公共 STUN 服务器：`stun:stun.l.google.com:19302`

- STUN 仅用于"打洞"（告知双方公网 IP/端口），不中转游戏数据
- 免费、稳定、全球可用
- PeerJS 内置 STUN 配置，无需额外设置

### 异常处理

| 异常 | 处理方式 |
|---|---|
| 房间号不存在 | 提示"房间不存在或已关闭" |
| 连接失败（NAT 严格） | 显示错误提示，建议双方尝试同一网络 |
| 对手中途断网 | 30 秒内未收到心跳 → 弹出"对手已掉线" |
| 浏览器不支持 WebRTC | 启动时检测，不支持则显示提示 |

### 房间号与辅助权限

- 房主创建房间时，生成的房间号末尾带 `*`（如 `DRAGON*`）
- 带 `*` 的玩家自动获得 AI 辅助权限
- 访客输入房间号时不带 `*`，无辅助权限
- 房间号 6 位随机字符（`[A-Z0-9]`），单次碰撞概率极低

## 4. AI 电脑辅助算法

### 三种辅助功能

| 功能 | 含义 | 触发时机 |
|---|---|---|
| 落子推荐 | 找出最优落子位置 | 每轮轮到房主时 |
| 威胁提醒 | 识别对手即将连五的威胁 | 每次对手落子后 |
| 胜率评估 | 评估当前局面胜率 | 每次落子后更新 |

### 核心引擎：Minimax + Alpha-Beta + 启发式评估

全部在浏览器本地运行，零 API Key、零 token、零联网。

#### 启发式评估函数

棋型评分表：

| 棋型 | 图示 | 分数 |
|---|---|---|
| 连五 | `●●●●●` | 1,000,000 |
| 活四 | `○●●●●○` | 100,000 |
| 冲四 | `●●●●_` | 10,000 |
| 活三 | `○●●●○` | 5,000 |
| 眠三 | `●_●●` | 500 |
| 活二 | `○●●○` | 500 |
| 眠二 | `●_●_` | 50 |
| 活一 | `○●○` | 10 |

评估方式：遍历棋盘所有位置，分别计算双方棋型得分，返回 `myScore - oppScore`。

胜率计算：使用 sigmoid 函数将分差映射到 0-100%。

#### Minimax 搜索

- 搜索深度 4-6 层（自适应：开局 4 层，中局 6 层，残局 8 层）
- 候选步筛选：只搜索已有棋子周围 2 格内的空位（约 10-30 格）
- 迭代加深：浅层先搜，保证 1 秒内出结果

#### Alpha-Beta 剪枝

跳过明显差的分支，搜索速度提升约 10 倍。

#### 搜索优化

| 优化 | 作用 |
|---|---|
| 候选步筛选 | 只搜棋子周围 2 格内空位 |
| 迭代加深 | 保证 1 秒内出结果 |
| 置换表 | 同一局面不重复搜索 |
| 杀手启发 | 优先尝试上次成功的走法 |

#### Web Worker

AI 搜索运行在 Web Worker 线程中，主线程（UI、点击、动画）不卡顿。

### "作弊级"辅助保障

| 技巧 | 说明 |
|---|---|
| 搜索深度偏向房主 | 房主回合搜 6 层，对手回合只搜 4 层 |
| 关键局面深度+2 | 双方都有活三以上时搜得更深 |
| 推荐保守 | 多个候选差不多时，推荐"最不会输"的位置 |

### 辅助输出形式

#### 落子推荐

- 主推荐位置：金色发光圆圈 (#FFD700)，脉动动画
- 备选位置：灰色光圈

#### 威胁提醒

- 对手即将连五的位置：红色半透明圆点 (#FF4444)，闪烁动画
- 文字说明威胁等级（🚨 紧急 / ⚠️ 注意 / ✅ 安全）

#### 胜率评估

- 进度条实时更新（你 X% / 室友 Y%）

## 5. 游戏界面与交互设计

### 三个页面状态

1. **首页**：创建房间 / 加入房间
2. **房间等待**：显示房间号 + 一键复制 + 等待动画
3. **对局中**：棋盘 + 侧栏（AI 面板 + 操作按钮）

### 棋盘区域

- 使用 HTML5 Canvas 渲染
- 棋盘底色：米白 (#F4ECD8)
- 棋盘线：深灰 (#3D3D3D)
- 黑色棋子：#1A1A1A，带轻微阴影
- 白色棋子：#FFFFFF，带黑色 1px 描边 + 阴影
- 落子动画：0.2s 缩放出现
- 最后落子标记：红色小方框
- 光标悬停：半透明预览棋子（仅自己回合）

### 侧栏（不对称设计）

- **房主**：看到 AI 辅助面板（推荐位 + 胜率 + 威胁）+ 操作按钮
- **访客**：只看到操作按钮（悔棋 / 和棋 / 认输），无 AI 面板

### 走子历史

棋盘下方一行，格式：`H4 G5 D7 F6 E8 ...`

### 关键交互流程

#### 落子

```
鼠标悬停 → 半透明预览 → 点击 → 落子动画 → 本地更新 → WebRTC 同步 → 切换回合
```

#### 悔棋

```
A 点击"悔棋" → 确认对话框 → 发送 UNDO_REQUEST → B 弹出同意/拒绝 → 结果通知 A
```

#### 和棋

```
任意一方点击"和棋" → 对方弹出同意/拒绝对话框
```

#### 胜负判定

每步落子后检查 4 个方向（水平、垂直、两条对角线），O(1) 时间。

#### 重新开始

对局结束 → 弹窗显示结果 → "再来一局" / "退出房间"
