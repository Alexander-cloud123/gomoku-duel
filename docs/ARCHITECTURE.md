# 架构说明（v2）

## 目标

- 纯静态、零运行时构建、无后端；P2P 联机
- 规则、渲染、网络、AI 解耦，核心逻辑可在 Node 中直接测试
- 移动端可用、可访问性达标、错误可恢复

## 模块

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 规则内核 | `js/rules/*` | 五子棋胜负、围棋提子/劫/超级劫/数子、坐标记谱、Zobrist |
| 状态机 | `js/game.js` | 回合、落子合法性、悔棋、终局点目、快照与恢复；**不碰 DOM** |
| 视图 | `js/board.js` | Canvas 渲染、DPR/缩放、指针与键盘输入、动画、提示标记 |
| 控制器 | `js/app.js` | 页面流转、对局装配、联机/PvE 调度、UI 同步 |
| 网络 | `js/net/*` | PeerJS 传输、协议校验、握手/心跳/重连/重同步 |
| AI | `js/ai/*` | 棋型识别、五子棋搜索、围棋启发式、Worker、主线程客户端 |
| UI | `js/ui/*` | 页面、模态、Toast、本地设置与战绩 |
| 入口 | `js/main.js` | 等待 DOM 后启动 |

## 数据流

```
BoardView(pointer) ──▶ app.onBoardMove ──▶ Session.sendMove ──▶ Transport ──▶ 对端 Session
       ▲                                        │                              │
       │                                   Game.applyMove ◀────────────────────┘
       │                                        │
       └──── BoardView.setState ◀── Game 事件 ◀┘
                                                │
                                          AIClient(Worker) ──▶ 提示 / PvE 出招
```

- `Game` 是唯一事实来源；所有 UI 都从 `snapshot()` 渲染
- `Session` 只负责把网络消息转成 `Game` 操作，并在失败时发起重同步
- 人机模式不经过 `Session`，由 `app` 直接调度 `AIClient` 与 `Game`

## 对局状态机

```
idle ──start──▶ playing ──(双虚手)──▶ scoring ──(双方确认)──▶ finished
                  │  │                                          ▲
                  │  └────────── 五连 / 和棋 / 认输 ─────────────┘
                  └── 悔棋：截断历史后从零回放
```

- 悔棋不逐手逆向恢复，而是截断 `moveHistory` 后 **重放**，避免提子、劫、气的恢复遗漏
- 围棋点目：死子集合双方共享，任何变更都会清空确认；双方确认且哈希一致才结算

## 网络设计

- 传输层只管连接与收发；协议层负责版本与字段校验；会话层负责流程
- 消息带 `seq`，重复丢弃、缺口重同步
- 房主是状态权威：访客重连后请求 `SYNC_STATE` 并恢复
- 心跳用时间戳判定，避免后台标签页定时器节流导致误判
- 请求类操作（悔棋/和棋/重开）单槽位 + 冷却，双方同时请求时后到者被拒绝
- 房间号即 PeerJS id；棋种/尺寸/贴目以房主为准，访客握手时自动采用；版本不符的拒绝只关闭本次连接，房主保留房间
- 每个新连接从 `seq = 0` 重新协商，避免房主复用会话时丢弃新访客的首条消息

## AI 设计

### 五子棋

- 迭代加深 Alpha-Beta，时间为预算、节点计数控制
- 置换表（Zobrist 双 32 位键）+ 走法排序（进攻/防守棋型分）
- 启发式评估：四方向逐行棋型统计
- 根节点先做「己方连五」「对手连五点」的即时判定
- 难度：入门在靠前候选中随机，进阶/高手按预算加深

### 围棋

- 一手评估：提子、气、叫吃、连接、位置权重、避免填眼
- 难度通过候选噪声与候选数量控制
- 试落子使用 `historyKeys` 做位置超级劫，避免产出会被规则拒绝的点
- 明确不追求棋力，只保证合法、可用、不阻塞

### Worker

- 模块 Worker，请求带 `id`；新请求会取消旧请求
- Worker 不可用时自动降级到主线程并缩短预算

## 渲染

- 静态层（底色/网格/星位/坐标）离屏缓存，动态层只画棋子与标记
- 后备缓冲按 `devicePixelRatio` 放大，CSS 尺寸由容器决定
- `pointer` 事件统一鼠标/触摸；`prefers-reduced-motion` 下 CSS 与 Canvas 落子动画均关闭

## 设计取舍

- 保持零构建：不为打包引入复杂度，测试与 lint 只作用于开发期
- 不引入服务端：无账号、无匹配、无观战
- 辅助默认双方可用，房主可关；旧 `*` 后缀兼容但不再有权限含义
- 围棋 AI 只做启发式，明确不在宣传上承诺棋力

## 扩展点

- 增加棋种：实现新的 `rules/*` 并在 `Game` 中分支
- 增加协议消息：在 `protocol.js` 增加类型与校验，在 `Session` 增加处理
- 替换传输：`Transport` 接口不变即可换成 WebSocket 等
